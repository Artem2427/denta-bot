# Phase 06.2 Plan 02: PricingPlan Reseed Script Summary

Idempotent `packages/db/prisma/seed-pricing.ts` reseed script (upsert-by-name, zero deleteMany/truncate) that wrote the design file's Старт/Клініка/Мережа sales copy into the real `PricingPlan` table, verified non-destructive across two consecutive runs.

## What Was Built

- `packages/db/prisma/seed-pricing.ts` — a sibling script to `seed.ts`, same `PrismaPg`/`PrismaClient` construction pattern, own header comment restating the "never truncate" convention. Defines a `PLANS` array of exactly 3 entries (Старт/Клініка/Мережа) mapped from the design file's `planData` onto the real `CreatePricingPlanDto` shape (`for` → `description`, `tag` → `isPopular` boolean, `items[]` → `features[]`, `cta` dropped per Pitfall 4). `main()` does `findFirst({ where: { name } })` → `update` if found, `create` if not, for each entry — never `deleteMany`/`truncate`.
- `packages/db/package.json` — added `db:seed:pricing` script, matching `db:seed`'s exact `dotenv -e ../../.env -- tsx ...` invocation pattern.
- Ran the script twice against the live dev DB. Row count for the 3 named plans (Старт/Клініка/Мережа) was 3 after both runs — no duplication, no data loss. 4 pre-existing unrelated rows (from prior-phase E2E/verification testing) were untouched by both runs, confirming the script only ever writes its own 3 named rows.
