## Decisions Made

- **Relocated `stagger-grid.tsx` instead of deleting it.** The plan listed it under `modules/home/*` for deletion, but the mandated pre-delete grep (Task 3's `read_first` step) surfaced 5 real importers across `modules/landing/` and `modules/blog/` — a genuine cross-page utility, not Home-page-specific dead code. Moved to `apps/web/shared/components/stagger-grid.tsx`, matching the project's established `shared/`=cross-page-components convention, and updated all 5 importers.
- **Fixed `proxy.ts`'s middleware matcher.** Task 2's own curl-based verification caught that the new redirect stubs were returning 404 instead of 307 — the next-intl middleware (added in Plan 06.2-01, `c5277b9`) was rewriting `/prices` to a nonexistent `/uk/prices` before Next could resolve the actual top-level route file. Added `/prices|demo|contacts` to the matcher's negative lookahead, matching the existing `/blog` exclusion and Task 2's own stated design intent (these 3 routes sit outside the `[locale]` segment, same tree position as `/blog`).

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] Relocated `stagger-grid.tsx` instead of deleting it with the rest of `modules/home/`**
- **Found during:** Task 3 (pre-delete grep, as the plan itself instructed)
- **Issue:** The plan's `files_modified` list `stagger-grid.tsx` under `modules/home/*` for deletion, but it is actively imported by `modules/landing/{features,how-it-works,reviews}.tsx` and `modules/blog/{related-posts,blog-filters}.tsx` — deleting it as planned would have broken the build with 5 dangling imports.
- **Fix:** Moved the file unchanged to `apps/web/shared/components/stagger-grid.tsx` and updated all 5 importers to the new path.
- **Files modified:** `apps/web/shared/components/stagger-grid.tsx` (new), `apps/web/modules/landing/{features,how-it-works,reviews}.tsx`, `apps/web/modules/blog/{related-posts,blog-filters}.tsx`

- **Committed in:** `767bac1` (Task 3 commit)

**2. [Rule 1 - Bug] Fixed `proxy.ts` matcher so `/prices`, `/demo`, `/contacts` redirect instead of 404ing**
- **Found during:** Task 2/3 boundary, while running the plan's own curl-based verify step
- **Issue:** `next-intl`'s middleware matcher (`apps/web/proxy.ts`, set up in Plan 06.2-01) excluded `/blog` but not `/prices`/`/demo`/`/contacts`. Since those 3 routes live outside the `[locale]` App Router segment, the middleware's locale-detection rewrite sent requests to a nonexistent `/uk/prices` internally, producing a 404 instead of the redirect stub's `307`.
- **Fix:** Extended the matcher's negative lookahead from `(?!api|_next|_vercel|blog|...)` to `(?!api|_next|_vercel|blog|prices|demo|contacts|...)`.
- **Files modified:** `apps/web/proxy.ts`
- **Verification:** After the fix, `curl -w '%{http_code} %{redirect_url}'` against `/prices`, `/demo`, `/contacts` returns `307` to `/#pricing`, `/#demo`, `/#lead` respectively; `/`, `/ru`, `/en`, `/blog` re-verified still `200` with no regression
- **Committed in:** `767bac1` (Task 3 commit)
