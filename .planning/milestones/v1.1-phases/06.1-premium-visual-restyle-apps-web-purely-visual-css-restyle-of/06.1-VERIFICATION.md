Independent verification found this claim is false — `apps/web/modules/demo/_data.ts`'s `scenarios` array (consumed by `bot-tab.tsx`, the live, in-scope "try the bot" Demo chat interface, not the out-of-scope admin-simulation tab) still contains 8 emoji characters embedded in simulated chat message text (📅, ⏰, 👨‍⚕️, 👩‍⚕️, ✅), none of which were touched by the gap-closure commit or documented as an accepted exception anywhere in the phase's SUMMARY.md files or commit history.

This is not a wiring/functionality defect — the primitives, tokens, and D-01..D-26 decisions are all faithfully and substantively implemented (15/16 truths verified with hard evidence). It is a completeness gap in the one hard client constraint ("Ніяких емодзі") that the team already recognized as important enough to warrant a dedicated gap-closure pass, and the pass was incomplete. Because the same "no copy change" tension that justified leaving `bot-tab.tsx:27`'s 🦷 untouched applies equally to these 8 occurrences (they're embedded in Ukrainian sentence text, not standalone decorative icons), this is presented as a gap requiring an explicit human decision — either (a) formally extend the documented exception list to cover `_data.ts`'s `scenarios`, or (b) strip these 8 occurrences (they read as decorative prefixes/suffixes, arguably closer to the icon-swap category that WAS fixed elsewhere in the same commit) — rather than a clear-cut code fix this verifier should prescribe unilaterally.
