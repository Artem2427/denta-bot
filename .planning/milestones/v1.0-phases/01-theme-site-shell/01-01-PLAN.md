## Phase Goal

**As a** site visitor, **I want to** see every page wrapped in a consistent, themeable header and footer with working navigation and a proper 404 for bad links, **so that** the site feels complete and on-brand from my very first visit.

This plan lays the token foundation (D-01/D-02/D-03) that Plan 01-02's shell components consume — it does not, by itself, produce a visible page change, but it is a prerequisite half of the same vertical slice (Walking Skeleton mode treats the shared-package theme layer and the shell components as one atomic capability, per `$HOME/.claude/gsd-core/references/planner-mvp-mode.md`).

<objective>
Re-theme `@repo/ui`'s shared design tokens with the design archive's light/dark palette (including the new `--brand` token), fix a pre-existing client-boundary bug in `sonner.tsx` that would otherwise break Plan 01-02's `<Toaster />` usage, and complete the THEME-02 shadcn-primitive audit for this phase's own scope.

Purpose: `packages/ui/styles/theme.css` is the single exported stylesheet consumed by `apps/web`, `apps/docs`, and `apps/admin-panel` — every subsequent page in every future phase inherits its tokens. Getting this right, and getting `sonner.tsx`'s RSC boundary right, is the actual engineering risk in Phase 1 per 01-RESEARCH.md ("the real risk in this phase is plumbing correctness, not design fidelity").
Output: Re-themed `packages/ui/styles/theme.css` (THEME-01), fixed `packages/ui/src/components/shadcn-ui/sonner.tsx` (unblocks THEME-03's Toaster wiring in Plan 01-02), and a documented shadcn-primitive audit finding (THEME-02).
</objective>
