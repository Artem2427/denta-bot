# PRD: Premium Design System (apps/web)

**Source:** Client-provided ТЗ (technical spec), pasted 2026-08-08 while Phase 2 execution was starting. Inserted as urgent Phase 01.1 (see `.planning/STATE.md` Roadmap Evolution).

## Scope decision (from user, not in the original ТЗ text below — READ FIRST)

This premium redesign applies to **`apps/web` only** — the marketing site (Home, Contacts, Demo's marketing/chat chrome, header, footer, shared layout). It does **NOT** apply to `packages/ui` (`@repo/ui`):

- `packages/ui` is **not** the foundation for this redesign. The marketing site gets its **own** component system (own palette, typography, spacing, motion) — do not build it by re-theming `@repo/ui` tokens.
- **Exception:** the Demo page's embedded admin-panel simulation (the dashboard/calendar/analytics mockup shown inside `/demo`'s "Admin" tab) stays on `@repo/ui` components, unchanged. It represents the real `apps/admin-panel` product, which is and remains built on `@repo/ui` — so it must keep looking like `@repo/ui`, not the new premium marketing system.
- Practical implication: new premium-site components live under `apps/web/shared/components/` (per the folder convention from Phase 2 planning — `app/`=routes only, `modules/<page>/`=page-specific, `shared/`=cross-page), not in `packages/ui/src/components/`. `packages/ui/styles/theme.css` is not modified by this phase.
- Phase 1's already-shipped shell (`apps/web/shared/components/{header,footer,logo,theme-toggle}.tsx` — currently built on `@repo/ui` Button/etc. with the brand-blue `#1d6be4` token) is in scope to be rebuilt against the new premium system, since header/footer are part of "the site."

## Downstream impact (for the planner to account for)

- Phase 2 (Home, Contacts & Demo) was already planned and verified (4 plans: 02-01..02-04) against the **old** design archive palette/content. Those plans are now stale for anything visual/component-related and will need replanning once this phase's design system exists — but their CONTEXT.md content transcription (page copy, section structure, data) remains valid and reusable content-wise.
- This phase's `must_haves`/artifacts should include enough (tokens, primitive component set, motion utilities, icon set) that Phase 2 replanning has a concrete system to build against, not just aesthetic guidance.

## Original ТЗ (client-provided, Ukrainian)

# ТЗ: Візуальне оновлення до преміум-класу
### Продукт: Чат-бот + сайт-презентація + демо адмінки для стоматологічних клінік

---

## 1. Мета документа

Довести візуальну частину продукту (сайт, вбудоване демо чат-бота, вбудоване демо адмінки) до рівня, який асоціюється з дорогим SaaS-продуктом enterprise-класу (референс — Linear, Stripe, Intercom, Notion), а не з типовим шаблонним лендингом чи "ще одним ботом для клінік". Клініка, яка бачить сайт уперше, повинна відчути: *"якщо у них так виглядає навіть демо — сам продукт точно надійний"*.

Візуальна якість тут — не декорація, а частина продажу. В B2B для медичної сфери довіра формується протягом перших 5 секунд перегляду, здебільшого через відчуття точності й уваги до деталей, а не через текст.

---

## 2. Позиціонування й тон

**Напрямок:** "Клінічна точність, людяна подача" — продукт, зроблений інженерами, які розуміються на медицині: спокійний, технологічний, точний, але з людяною теплотою в деталях взаємодії.

**Уникати:**
- Типової медичної естетики (стерильний білий + синій + іконка зуба/хреста)
- Типового SaaS-конструктора (сірий, безликий, дефолтні iconpack-іконки)
- Emoji в інтерфейсі, надмірних градієнтів, стокових фото усміхнених лікарів у білих халатах
- Будь-якої "продажної" мови на сайті — тон стриманий, фактологічний

---

## 3. Кольорова палітра

| Роль | Колір | HEX | Застосування |
|---|---|---|---|
| Основний темний | Deep navy | `#1A2B3D` | Заголовки, hero-фон, текст на світлому |
| Акцент довіри | Teal | `#2C7A7B` | Іконки, лінії, вторинні акценти, графіки |
| Фон | Warm white | `#FAFAF8` | Основний фон сторінки (тепліший за #FFFFFF) |
| Акцент дії | Coral | `#E86B5A` | Кнопки CTA, активні елементи чат-бота, сигнатурна деталь |
| Текст | Graphite | `#2D3436` | Основний текст, м'якший за чорний |
| Успіх (в демо адмінки) | Sage | `#7A9E7E` | Підтвердження, статус "вільно" |
| Увага (в демо адмінки) | Amber muted | `#D4A24C` | Статус "очікує підтвердження" |

**Правило використання coral:** тільки для дії або живого моменту взаємодії (кнопка, повідомлення бота, що з'явилось, підтвердження). Ніколи як фон великих площ — його цінність саме в рідкісності.

---

## 4. Типографіка

**Заголовки:** геометричний sans-serif з характером і впевненістю — Söhne, General Sans, Inter Display, або Neue Montreal. Без serif — тут доречність саме precision/tech, не люкс-декоративність.

**Текст:** той самий шрифт або споріднений (Inter, Söhne Buch) — вищий контраст ваги між заголовком (600–700) і тілом (400), ніж зазвичай, щоб ієрархія читалась миттєво без зусиль (важливо для зайнятого адміністратора клініки, що переглядає сайт побіжно).

**Шкала розмірів (рекомендована, rem):**
- H1: 3.5–4.5 (hero)
- H2: 2.25–2.75 (секції)
- H3: 1.5 (підзаголовки карток)
- Body: 1–1.125
- Caption/label: 0.8125, letter-spacing +0.02em, uppercase для міток статусів

**Міжрядковий інтервал:** 1.5 для тексту, 1.1–1.2 для заголовків.

---

## 5. Сітка, простір, форма

- **Багато білого простору** — впевненість через стриманість, продукт не намагається нічого "кричати"
- **Скруглення:** помірне, 8–12px для карток і кнопок, 6px для інпутів — точність, а не грайливість (уникати капсул/пігулок, це знижує "серйозність" продукту)
- **Тіні:** м'які, багатошарові (soft depth: 2–3 накладені тіні різної розмитості замість однієї різкої `box-shadow`) — відчуття продукту, зробленого з увагою до деталей
- **Сітка:** 12-колонкова, максимальна ширина контенту 1200–1280px, генерозні відступи між секціями (96–140px на десктопі)

---

## 6. Іконографія та зображення

- Іконки — лінійні, тонка обводка (1.5px), єдиний стиль по всьому сайту (рекомендація: Phosphor Icons або кастомний набір, не Font Awesome/дефолтні)
- Жодної домінантної іконографії хреста/зуба — це виглядає дешево й дублює конкурентів
- Скріншоти інтерфейсу бота/адмінки — реальні, з правдоподібними даними (реалістичні імена, часові слоти), не lorem ipsum і не абстрактні 3D-blob ілюстрації
- Якщо потрібні ілюстративні елементи — тонка лінійна графіка в дусі медичних схем/діаграм, а не мультяшні персонажі

---

## 7. Демо чат-бота — деталізована специфікація

Це один із двох головних "продажних" елементів сайту. Має виглядати як реальний, працюючий продукт, вбудований у сторінку, а не картинка.

**Структура інтерфейсу:**
- Реалістичний месенджер-вигляд (за референсом Telegram/iMessage): бульбашки з правильними відступами, timestamp під кожним повідомленням, статус "доставлено/прочитано" для повідомлень користувача

**Поведінка й анімація:**
| Момент | Специфікація |
|---|---|
| Перед відповіддю бота | Індикатор друкування — три крапки, що пульсують по черзі (`opacity` 0.3→1→0.3, delay 200ms між крапками) |
| Поява повідомлення | Bounce/slide-in знизу (translateY 8px→0, opacity 0→1), тривалість 250ms, easing `cubic-bezier(0.16, 1, 0.3, 1)` |
| Послідовність повідомлень | Затримка 300–500ms між повідомленнями — імітує реальний темп розмови, не всі одразу |
| Quick-reply кнопки | З'являються після відповіді бота, coral-обводка, легкий hover-lift |
| Скрол демо | Автоскрол до нового повідомлення плавний (не миттєвий jump) |

**Сценарій демо-діалогу:** показати реальний use-case (запис на прийом → вибір лікаря → вибір часу → підтвердження → нагадування) — це і є "продаж" функціоналу без єдиного маркетингового слова.

---

## 8. Демо адмінки — деталізована специфікація

**Формат:** інтерактивний макет, а не статичний скріншот — навіть якщо функціонально обмежений (клікабельні дати в календарі, hover-стани на картках записів).

**Компоненти для демонстрації:**
- Календар записів з кольоровим кодуванням статусів (sage/coral/amber)
- Картка пацієнта при кліку на запис (ім'я, історія візитів, нотатки)
- Блок аналітики: завантаженість кабінетів, кількість записів за тиждень

**Анімація:**
| Елемент | Специфікація |
|---|---|
| Числа в аналітиці | Лічильник "накручується" від 0 до фінального значення при появі в полі зору скролу, 800–1200ms, easing ease-out |
| Стовпчикові графіки | Виростають знизу вгору при появі в полі зору, staggered по 80ms між стовпчиками |
| Перемикання вкладок | Fade-transition (150ms), не миттєва зміна контенту |
| Hover на записі в календарі | Легкий lift + tooltip з деталями, 150ms |

> **Scope note (see decision above):** the demo-admin visual system itself stays on `@repo/ui` — this section's *animation timing/behavior* specs still apply to whatever `@repo/ui`-based implementation Phase 2 builds, but the component styling should not be rebuilt in the new premium palette.

---

## 9. Анімації сайту загалом

**Scroll-triggered reveals:**
- Секції з'являються з fade + translateY(20px→0) при вході в viewport (Intersection Observer, threshold ~0.15)
- Елементи всередині секції — staggered, зсув 60–100ms між сусідніми елементами, не одночасна поява

**Parallax:**
- Легкий, тільки в hero-секції — фонові елементи рухаються на 20–30% швидкості скролу відносно переднього плану, створює глибину без ефекту "розважального сайту"

**Hover-мікровзаємодії:**
- Картки послуг/фіч: `translateY(-4px)` + посилення тіні, 200ms — уникати `scale()`, він виглядає дешевше й менш "продуктово"
- Кнопки: зміна кольору фону + легкий lift, без bounce-ефектів

**Курсор-реактивність (опційно, тільки hero):**
- Один декоративний елемент, що ледь зсувається за курсором (magnetic effect, амплітуда 8–15px) — підсилює відчуття "живого" продукту, не переускладнювати

**Easing:** усюди `cubic-bezier(0.16, 1, 0.3, 1)` (плавне уповільнення, "expo-out") замість лінійних переходів — лінійні анімації читаються як механічні й дешеві.

**Головне правило анімацій:** кожна анімація повинна щось *підтверджувати* (бот друкує → відповідь формується; графік росте → дані реальні), а не просто прикрашати. Декоративний рух без функціонального сенсу — перший сигнал "AI зробив красиво", а не "продукт з розумінням деталей".

---

## 10. Сигнатурна деталь (наскрізний елемент)

Один повторюваний елемент через увесь сайт — тонка coral-риска або крапка, що з'являється саме в момент "дії" (нове повідомлення бота, підтвердження запису, активний статус в адмінці). Дисципліновано лише в точках взаємодії, не розкидано декоративно по всьому дизайну. Це і є впізнаваний "підпис" бренду продукту.

---

## 11. Доступність і продуктивність

- Контраст тексту — мінімум WCAG AA (4.5:1 для основного тексту)
- Видимий `focus-visible` стан для всіх інтерактивних елементів (не просто прибирати outline)
- `prefers-reduced-motion: reduce` — усі декоративні анімації (parallax, курсор-реактивність, bounce) вимикаються або спрощуються до простого fade
- Анімації на CSS transform/opacity (не top/left/width) для продуктивності на слабших пристроях
- Lazy-load для важких демо-блоків (чат-бот, адмінка) — не блокувати перше завантаження сторінки

---

## 12. Мобільна версія

- Демо чат-бота на мобільному — той самий рівень якості анімацій, не спрощена версія
- Демо адмінки на мобільному — можна показати як vertical-scroll preview з поясненнями замість спроби втиснути повноцінний dashboard
- Кнопка "Запросити демо" — sticky або завжди легко досяжна

---

## 13. Технічна реалізація (рекомендації)

- Framer Motion (React) або GSAP — для scroll-reveals і складних послідовностей анімації чат-бота
- Intersection Observer API — для тригерів анімації при скролі, без бібліотек-важковаговиків
- Шрифти — самостійний хостинг (self-hosted woff2), не покладатися на сторонні CDN для критичного рендерингу
- Перевірка продуктивності: Lighthouse Performance score не нижче 85 навіть з анімаціями

---

## 14. Критерій приймання ("чи вийшло преміум")

Фінальний чек-лист перед здачею:

- [ ] Жоден елемент не виглядає як дефолтний Bootstrap/Tailwind-компонент без кастомізації
- [ ] Демо чат-бота виглядає як реально працюючий продукт, а не картинка з написом "демо"
- [ ] Жодна анімація не декоративна без функціонального сенсу
- [ ] Палітра застосована послідовно, coral використаний рідко й лише для дії
- [ ] Типографічна ієрархія читається миттєво, без потреби вчитуватись
- [ ] Сайт однаково сильний на мобільному, не "обрізана" версія десктопу
- [ ] Перше враження (перші 3 секунди hero) відповідає рівню Linear/Stripe/Intercom
