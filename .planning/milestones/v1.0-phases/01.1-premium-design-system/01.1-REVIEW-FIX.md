## Fixed Issues

### CR-1: Fixed header renders over page content (no top offset reserved)

**Files modified:** `apps/web/app/layout.tsx`
**Commit:** 17db6fa
**Applied fix:** Added `pt-16 lg:pt-20` to the `<main>` element in `RootLayout`, matching `Header`'s `h-16`/`lg:h-20` height so the shell reserves space for the fixed header by construction rather than relying on every future page to compensate individually.

### WR-1: Dark-mode `ThemeToggle` produces no visible change (missing dt-* dark tokens)

**Files modified:** `apps/web/shared/components/header.tsx`
**Commit:** c9f3fc5
**Applied fix:** Went with the review's descope option rather than inventing an unreviewed dark palette: removed the `ThemeToggle` import and both its usages (desktop actions row, mobile actions row) from `Header`. `premium-theme.css` defines only light values for every `--color-dt-*` token with zero `.dark`/`prefers-color-scheme` overrides, and no `.planning/` decision (D-05 or otherwise) ever scoped a dark palette for this phase — so shipping a functional-looking but visually-inert toggle was the actual defect. `theme-toggle.tsx` itself is left in place, unused, for future dark-mode work once a palette decision exists.

### WR-2: WCAG AA contrast failure on `text-dt-coral` link hover states

**Files modified:** `apps/web/shared/components/header.tsx`, `apps/web/shared/components/footer.tsx`
**Commit:** e5e92dd
**Applied fix:** Replaced `hover:text-dt-coral` (3.01:1, fails 4.5:1 AA) with `hover:text-dt-teal` (4.81:1, passes AA) across all 10 occurrences — 1 in `header.tsx` (desktop nav links) and 9 in `footer.tsx` (product/company link columns, contact email/Telegram links). Chose `dt-teal` over `dt-navy` to avoid visually colliding with the existing `text-dt-navy` active-link state. Left the unrelated `bg-dt-coral` background-on-hover usage in the footer's social icon buttons untouched — that's a background/icon use, not the text-on-`dt-warm-white` contrast pattern this finding covers.

### WR-3: Header/Footer use Tailwind's default `.container` instead of the `Container` primitive

**Files modified:** `apps/web/shared/components/header.tsx`, `apps/web/shared/components/footer.tsx`
**Commit:** 529ecf0
**Applied fix:** Replaced the hardcoded `<div className="container mx-auto px-4 lg:px-8">` wrapper in both components with `<Container>` (importing from `./container`). In `Footer`, preserved the extra `py-16 lg:py-24` vertical padding by passing it as `className` to `Container`, relying on `cn()`'s `tailwind-merge` to compose cleanly with `Container`'s own `px-4 lg:px-8` base classes. Both components now share the same flat 1280px (`--dt-container-max`) cap as the rest of the site instead of Tailwind's breakpoint-stepped default max-width.

### WR-4: Icon-only buttons ship with no accessible name

**Files modified:** `apps/web/shared/components/header.tsx`, `apps/web/shared/components/theme-toggle.tsx`
**Commit:** 2da23e9
**Applied fix:** Added `aria-label={isMobileMenuOpen ? 'Закрити меню' : 'Відкрити меню'}` and `aria-expanded={isMobileMenuOpen}` to the header's mobile menu toggle `PremiumButton` (confirmed `PremiumButton` spreads `...props` onto the underlying `<button>`, so these pass through correctly). Added the same `<span className="sr-only">Перемкнути тему</span>` used in `ThemeToggle`'s mounted branch to its pre-mount (`!mounted`) fallback branch, so the control is never rendered without an accessible name during SSR/first paint.

### WR-5: Mobile menu Motion animation ignores `useReducedMotion()`

**Files modified:** `apps/web/shared/components/header.tsx`
**Commit:** a6be02c
**Applied fix:** Imported `useReducedMotion` from `motion/react` and called it in `Header`. The mobile nav's `motion.div` `initial`/`animate`/`exit`/`transition` props now branch on `prefersReducedMotion`: when true, they use opacity-only variants (no `height` animation) with a near-instant `0.01`s duration; when false, the original height+opacity animation with `EASE_DT_EXPO_OUT` is unchanged. Mirrors the pattern already used in `Reveal` (`apps/web/shared/components/reveal.tsx`), since `premium-theme.css`'s CSS-only `prefers-reduced-motion` rule has no effect on Motion's WAAPI-driven animations.
