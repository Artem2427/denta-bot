## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Public internet → apps/server POST /leads | Unauthenticated browser clients (marketing site visitors) send arbitrary POST bodies to a genuinely new, public, write-capable endpoint |
| apps/web client bundle → apps/server | Client-side `fetch()` from the browser to `NEXT_PUBLIC_API_URL` — request/response fully visible to the visitor's browser devtools |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-01 | Denial of Service | POST /leads handler | high | mitigate | `@nestjs/throttler` `ThrottlerGuard` + `@Throttle({ default: { limit: 5, ttl: 60000 } })` applied method-level (Task 1) — unauthenticated public write is rate-limited from day one per D-03 |
| T-06-02 | Tampering | CreateLeadDto / POST /leads | medium | mitigate | Global `ValidationPipe({ whitelist: true, forbidNonWhitelisted: true, transform: true })` already active (main.ts) strips any field not declared on `CreateLeadDto` — `status`/`updatedById`/`clinicId` cannot be set by the client; `source` is restricted to `@IsEnum(LeadSource)` (contacts\|demo only) |
| T-06-03 | Spoofing | `source` field on CreateLeadDto | low | accept | A client can freely set `source: 'contacts'` or `'demo'` regardless of which form actually submitted it — `source` is a soft analytics/triage tag consumed by PlatformAdmin, not a security boundary; misattribution has no security impact |
| T-06-04 | Information Disclosure | POST /leads 201 response body | low | accept | The response echoes back only the submitter's own just-submitted data — no cross-user data exposure |
| T-06-05 | Tampering (stored) | name/message fields rendered later in apps/platform-admin's Lead detail screen | low | accept | React's default JSX rendering auto-escapes string content; apps/platform-admin's Lead detail view (built in Phase 5) renders these as plain text with no `dangerouslySetInnerHTML`; Prisma's parameterized queries prevent SQL injection — canon OWASP injection/XSS mitigation, not re-implemented here |

## Prohibitions (fallback prohibition-probe, adversarial recall + precision pass)

Kept, values-based, not covered by routine engineering or OWASP/GDPR canon:
- Must not silently enroll the Lead submitter in any marketing/newsletter list or imply consent beyond what the Contacts/Demo form explicitly states — the Lead record is a discrete inquiry, not a subscription.
