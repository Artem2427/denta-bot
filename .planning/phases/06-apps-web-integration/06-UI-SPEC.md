# Phase 6 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

## Design System

| Property | Value |
|----------|-------|
| Tool | none — `apps/web` uses its own bespoke "premium" design system (`dt-*` tokens), established in Phase 01.1. NOT `@repo/ui`/shadcn (per CLAUDE.md's Phase 01.1 pivot). This phase extends that system; it does not introduce a new one. |
| Preset | not applicable |
| Component library | `radix-ui` unstyled primitives only, wrapped in bespoke `Premium*` components (`shared/components/premium-*.tsx`). This phase adds exactly one new primitive wrapper: `PremiumDialog` (Radix `Dialog`, styled with `dt-*` tokens — no dialog/modal component exists in `apps/web` yet). |
| Icon library | `@phosphor-icons/react` (`weight="regular"` / `weight="fill"` — matches existing usage, e.g. `Clock`, `MagnifyingGlass`, `CheckCircle`, `Check`) |
| Font | `Inter` via `next/font/google`, split into `--font-dt-heading` (weights 600/700) and `--font-dt-body` (weights 400/500) — `apps/web/app/fonts.ts`. No new font needed this phase. |

**Source of truth:** `apps/web/app/premium-theme.css` (Tailwind `@theme` block). This phase reuses every existing token; it adds zero new `dt-*` tokens (see Spacing/Typography/Color below — all "established" rows are already-shipped values, cited so planner/executor don't reinvent them).

## Spacing Scale

Declared values (already established in `premium-theme.css` / existing component usage — must be multiples of 4, reused as-is):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-text gaps (e.g. badge icon spacing) |
| sm | 8px | Compact stacked elements (form label → input gap: `space-y-2`) |
| md | 16px | Default element spacing |
| lg | 24px | Card padding (`PremiumCard` = `p-6`), form field group spacing (`space-y-6`) |
| xl | 32px | Modal padding on `sm:` breakpoint+ (new `PremiumDialog`, see below) |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing |

**Exceptions for this phase:**
- New `PremiumDialog` content padding: `p-6` (24px) on mobile, `sm:p-8` (32px) on `sm:`+ — matches `PremiumCard`'s existing `p-6` base, scaled up one step for the modal's more contained viewport real estate.
- Modal max-width: `max-w-md` (28rem) — matches `ContactForm`'s natural single-column card width so the reused form doesn't need new responsive breakpoints.

## Typography

Already established (`premium-theme.css` — reused verbatim, zero new sizes/weights introduced):

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 18px (`text-dt-body`, `1.125rem`) | 400 (`font-dt-body`) | 1.5 |
| Label / caption | 13px (`text-dt-caption`) / `text-sm` (14px) for form labels | 500 (`font-medium`) | default |
| Heading (h3 — card/modal titles) | 24px (`text-dt-h3`, `1.5rem`) | 600 (`font-semibold`) via `font-dt-heading` | 1.15 |
| Display (h1 — page hero) | fluid `clamp(2.25rem, 6vw+1rem, 4rem)` | 700 (`font-bold`) via `font-dt-heading` | 1.15 |

**This phase's new UI (Demo modal, empty/error states) uses only these four existing roles** — no new size/weight combination is introduced. Modal title uses the `h3` role (matches `ContactForm`'s `<h2 className="text-dt-h3 font-dt-heading font-semibold text-dt-navy">` pattern exactly).

## Color

Already established (`premium-theme.css` — 60/30/10 split as already shipped across the site; reused verbatim):

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `dt-warm-white` (`#fafaf8`) | Page background, card surfaces, modal surface |
| Secondary (30%) | `dt-navy` (`#1a2b3d`) | Body text, headings, borders (`border-dt-navy/10`, `/20`), overlay tint |
| Accent (10%) | `dt-coral` (`#e86b5a`) | Reserved for: primary CTA buttons (submit/trigger), active filter-pill state, "Популярний" plan badge, form field error text |
| Secondary accent | `dt-teal` (`#2c7a7b`) | Reserved for: success icon background/foreground (`CheckCircle`), category badges, comparison-table checkmarks |
| Destructive | not applicable | No destructive actions exist in `apps/web` this phase (public forms only *create* Lead records — no delete/edit-in-place UI). Do not introduce a red/destructive color. |

**Fix required while touching this code (Pitfall — off-palette color found during research):** `apps/web/modules/prices/pricing-cards.tsx` currently renders its feature-list checkmark with `text-green-500` — an off-brand Tailwind default color, inconsistent with `comparison-table.tsx`'s `CheckCell` which correctly uses `text-dt-teal`. Since this file is already being modified to consume fetched `PricingPlan[]` data (CMS-04), change `text-green-500` → `text-dt-teal` in the same pass.

**Accent reserved for (explicit list, this phase's new surfaces):**
- Demo CTA trigger button (`variant="coral"`)
- Modal submit button (`variant="coral"`, reused from `ContactForm`)
- Inline form validation error text (`text-dt-coral`, matches `ContactForm`'s existing `<p className="text-sm text-dt-coral">`)
- Toast error copy (rendered via `sonner`'s default error styling — no custom color override)

## Copywriting Contract

All copy in Ukrainian, matching the existing site's tone (direct, warm, second-person-plural formal — see `ContactForm`'s "Дякуємо!" pattern as the tonal baseline).

| Element | Copy |
|---------|------|
| Demo CTA trigger (D-10) | `Замовити демо` — `PremiumButton variant="coral"`, placed in `/demo`'s header block next to the "DEMO MODE" badge |
| Modal title | `Замовити демо` (matches `ContactForm`'s `<h2>` pattern/position) |
| Modal submit button | `Надіслати заявку` (reused verbatim from `ContactForm` — same action, same label, per D-11's "reuse the same fields and schema") |
| Modal submit — loading state (NEW this phase) | Button label changes to `Надсилаємо…`, `disabled={form.formState.isSubmitting}` — applies identically to `ContactForm`'s submit button, which currently has **no** loading state (its mocked `setTimeout` never needed one; the real `fetch()` call now can be slow/fail) |
| Form submit success (both forms) | Heading `Дякуємо!` / body `Ваша заявка успішно надіслана. Ми зв'яжемося з вами найближчим часом.` (reused verbatim from `ContactForm`'s existing success block) — modal stays open showing this state; user closes via `Закрити` button, overlay click, or ESC (Radix default) |
| Form submit error — generic (NEW this phase) | Toast (`sonner`, `toast.error(...)`): `Не вдалося надіслати заявку. Спробуйте ще раз.` Form fields remain populated (no reset), submit button re-enabled. |
| Form submit error — rate-limited (429, NEW this phase, D-03) | Toast: `Забагато спроб. Зачекайте хвилину і спробуйте ще раз.` (distinct copy from generic error — the user needs to know *waiting* fixes it, not resubmitting immediately) |
| Blog — empty state (zero published posts) | Heading `Матеріалів поки немає` / body `Ми вже готуємо перші статті. Загляньте трохи пізніше.` — replaces the entire hero + grid section |
| Blog — filtered-search empty (EXISTING, unchanged) | `За вашим запитом нічого не знайдено` (`blog-filters.tsx`, already shipped — keep as-is, do not confuse with the empty-state row above; this one is search/category-filter-specific) |
| Blog/Prices — page-level fetch error (NEW this phase, 5xx/network) | Heading `Щось пішло не так` / body `Не вдалося завантажити дані. Спробуйте оновити сторінку.` / retry button `Оновити` (Next.js `error.tsx` boundary's `reset()`) |
| Prices — empty state (zero published plans) | Heading `Тарифи тимчасово недоступні` / body `Ми оновлюємо тарифні плани. Зв'яжіться з нами, щоб дізнатися актуальні умови.` / CTA link `Зв'язатися з нами` → `routes.contacts` |
| Blog — "Завантажити ще" button (EXISTING — REMOVE this phase) | D-08 fetches all published posts in one request (no pagination) — this button is now dead/misleading once real data replaces the mock array. Remove it from `app/blog/page.tsx`. |
| Destructive confirmation | Not applicable — no destructive actions introduced this phase. |

## UI Considerations

Applicable state considerations resolved: 13 covered, 2 backstop, 0 unresolved.

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| loading | Contact form, Demo modal form (`form`) | ✅ covered | Submit button label becomes `Надсилаємо…` and is `disabled` while `form.formState.isSubmitting` is true — see Copywriting Contract row "Modal submit — loading state" |
| error | Contact form, Demo modal form (`form`) | ✅ covered | Non-2xx/network failure shows a `sonner` toast error (generic or rate-limit copy per response status), form data is preserved, submit re-enabled — see Copywriting Contract "Form submit error" rows |
| long-text | Contact form / Demo modal message field (`form`) | ✅ covered | `PremiumTextarea` fixed at `rows={4}`, natively scrolls for overflow — no truncation needed, existing behavior unchanged |
| empty | Blog list (`list-collection`) | ✅ covered | Zero published posts → dedicated empty state (heading + body), hero + grid both suppressed — see Copywriting Contract "Blog — empty state" |
| zero-one-many | Blog list (`list-collection`) | ✅ covered | Exactly 1 published post total → featured/hero card renders (D-12: newest post), grid below renders nothing (not the "0 results" search-empty message — that's reserved for filtered search only); 0 posts → full empty state; many posts → existing grid layout, unchanged |
| overflow / long-text | Blog cards — title/excerpt (`list-collection`) | 🧪 backstop | Real CMS-authored titles/excerpts (via `apps/platform-admin`) are not curated-length like the mock data. Apply `line-clamp-2` to card title, `line-clamp-3` to card excerpt in `blog-filters.tsx`'s card markup to prevent card-height blowout in the grid. No automated visual-regression test exists for this — flagged as a held-out visual check at verify time. |
| error | Blog list/detail, Prices page (`list-collection`/`static-content`) | ✅ covered | 5xx/network fetch failure at the Server Component level → Next.js `error.tsx` boundary (`app/blog/error.tsx`, `app/prices/error.tsx`) renders "Щось пішло не так" + retry — see Copywriting Contract |
| populated | Blog detail page (`static-content`) | ✅ covered | Existing `PostBody`/related-posts rendering logic is unchanged — only the data source changes (fetched vs. static import), per Pattern 3 |
| empty | Prices page — pricing cards (`list-collection`) | ✅ covered | Zero published plans → dedicated empty state with a Contacts CTA — see Copywriting Contract "Prices — empty state" |
| zero-one-many | Prices page — pricing cards (`list-collection`) | ✅ covered | Card grid layout is no longer hardcoded to `lg:grid-cols-3` (3 mock plans) — must flex to actual published-plan count: 1 plan → single centered card (`max-w-md mx-auto`), 2 plans → `lg:grid-cols-2`, 3+ plans → `lg:grid-cols-3` (wraps for >3) |
| zero-one-many | Comparison table (`list-collection`) | ✅ covered | Comparison table is only rendered when ≥2 published plans exist — a 0-or-1-plan comparison has no comparative value; `app/prices/page.tsx` conditionally omits `<ComparisonTable />` below that threshold |
| overflow / long-text | Comparison table rows (`list-collection`) | 🧪 backstop | Per D-05/D-06, rows are now derived 1:1 from raw `features[]` strings (previously hand-curated short labels, e.g. "Записи на місяць"). A long feature phrase (e.g. "До 500 записів/місяць") sits directly in the row label cell with no truncation — table already has `overflow-x-auto` on its wrapper for horizontal scroll on narrow viewports; no line-clamp needed on row labels (single-line feature phrases are expected, not paragraphs) but not verified against real authored content — flagged as a held-out visual check at verify time. |
| overflow | Comparison table wrapper (`nav`/`static-content`) | ✅ covered | Existing `<div className="overflow-x-auto">` around the `<table>` handles narrow-viewport horizontal scroll — unchanged, reused as-is |
| populated | Pricing cards checkmark color (`list-collection`) | ✅ covered | Fixed to `text-dt-teal` (was off-palette `text-green-500`) — see Color section "Fix required" note |

## New Component Contract: `PremiumDialog`

No dialog/modal primitive exists in `apps/web/shared/components/` yet (confirmed by directory listing). This phase's Demo modal (D-10/D-11) requires exactly one new wrapper component, styled to match the existing `Premium*` family:

| Property | Spec |
|----------|------|
| Base primitive | `radix-ui`'s `Dialog` export (`import { Dialog as DialogPrimitive } from 'radix-ui'`) — same import shape already proven in `packages/ui/src/components/shadcn-ui/dialog.tsx`, but re-styled with `dt-*` tokens, not shadcn's |
| Overlay | `bg-dt-navy/40` with `backdrop-blur-sm`, fades in/out via Radix `data-[state=open]`/`data-[state=closed]` attributes, `duration-200` (matches `PremiumButton`/`PremiumCard`'s existing transition timing) |
| Content surface | `bg-dt-warm-white`, `rounded-dt-card`, `shadow-[var(--shadow-dt-hover)]`, `border border-dt-navy/10` — visually identical language to `PremiumCard` |
| Content sizing | `max-w-md` (28rem), `p-6 sm:p-8`, `max-h-[90vh] overflow-y-auto` (scrolls internally if content exceeds viewport height — mobile keyboard-open scenario) |
| Close affordance | `X` icon button (Phosphor `X`, `weight="regular"`) top-right, `variant="ghost" size="icon"` `PremiumButton`; plus Radix defaults: ESC key and overlay-click both close |
| Focus management | Radix default focus trap — no custom implementation (per research's "Don't Hand-Roll" guidance) |
| Trigger | `PremiumButton variant="coral"` reading "Замовити демо" (see Copywriting Contract), rendered in `/demo`'s header block adjacent to the "DEMO MODE" badge, visible regardless of active tab (D-10) |
