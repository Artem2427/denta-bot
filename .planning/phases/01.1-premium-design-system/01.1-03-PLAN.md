<objective>
Build the site-wide motion utility layer: a native-`IntersectionObserver` `useInView` hook, a shared `motion.ts` constants module (easing, reveal/hover variants), a `Reveal` scroll-animation wrapper component, and the `SignatureMark` recurring coral action-indicator — all respecting `prefers-reduced-motion` and animating only `transform`/`opacity`. Per D-43, `motion` (Motion/`motion.dev`, formerly Framer Motion) is the chosen animation library — installed and legitimacy-gated in Plan 01 — driving `Reveal` and (in Plan 04) the header's mobile-menu transition; per D-44, scroll-triggered detection uses the native `IntersectionObserver` API via the hand-rolled `useInView` hook below, not a third-party scroll-animation package.

Purpose: DESIGN-02 — the motion system's reusable primitives (scroll-triggered reveals D-28, the D-32 easing curve used everywhere, the D-34 signature detail), built once so every future consumer (this phase's header mobile-menu, and Phase 2's page sections/chat-bot demo) shares identical timing and reduced-motion behavior. `Reveal` and `SignatureMark` both exist to make D-33's golden rule concrete at the primitive level — `Reveal` only ever animates content that is already present and meaningful (never a decorative-only flourish), and `SignatureMark` is documented (Task 2) as gated to genuine interaction/action moments, not scattered decoration.
Output: 4 new files under `apps/web/shared/`, ready for Plan 04's header rebuild and Phase 2's page content.
</objective>
