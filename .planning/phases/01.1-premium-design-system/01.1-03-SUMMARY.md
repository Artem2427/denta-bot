## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Guarded possibly-undefined `IntersectionObserver` entry in `use-in-view.ts`**
- **Found during:** Task 2's `pnpm --filter web check-types` verify step
- **Issue:** `apps/web`'s tsconfig treats array-destructured `entry` from `([entry]) => ...` as possibly `undefined` (`noUncheckedIndexedAccess`-style strictness inherited from `@repo/typescript-config`), causing `TS18048` on `entry.isIntersecting`
- **Fix:** Changed to `entry?.isIntersecting` — behavior-identical (an `IntersectionObserver` callback with `threshold` config always delivers exactly one entry per observed target in practice; the optional chain is a pure type-safety guard, not a logic change)
- **Files modified:** `apps/web/shared/hooks/use-in-view.ts`
- **Verification:** `pnpm --filter web check-types` no longer reports any error in `shared/`; all Task 1 grep-based acceptance criteria re-verified passing after the edit
- **Committed in:** `9800dd2`

**2. [Rule 3 - Blocking] Created `apps/web/shared/lib/cn.ts`, not declared in this plan's `files_modified`**
- **Found during:** Task 2 — `signature-mark.tsx`'s action step explicitly requires `import { cn } from '@/shared/lib/cn'`, but that file does not exist anywhere in this worktree (it wasn't created by Plan 01, this plan's only declared dependency)
- **Issue:** Sibling wave-2 plan `01.1-02` (running in parallel, in a separate worktree) is the plan that declares and creates `apps/web/shared/lib/cn.ts` — but plan `01.1-03`'s `depends_on` frontmatter only lists `["01.1-01"]`, not `01.1-02`.
