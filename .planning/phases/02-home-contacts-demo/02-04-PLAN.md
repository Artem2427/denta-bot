<objective>
Restructure `apps/web` to match the newly-locked three-layer folder convention — `apps/web/app/` holds route files ONLY (`page.tsx`, `layout.tsx`, `not-found.tsx`); `apps/web/shared/{components,lib}/` holds cross-page code; `apps/web/modules/<page>/` is reserved for page-scoped code — before Wave 2 builds the Home, Demo, and Contacts pages on top of it. Relocates Phase 1's `apps/web/components/{header,footer,logo,theme-toggle}.tsx` to `apps/web/shared/components/` and `apps/web/lib/routes.ts` to `apps/web/shared/lib/routes.ts`, updating `apps/web/app/layout.tsx` and `apps/web/app/not-found.tsx`'s import paths accordingly, with zero behavior change.

Purpose: this is a structural prerequisite, not a feature. The new convention was locked by the user after 02-01/02-02/02-03 were already written and committed against the old flat `apps/web/components/`/`apps/web/lib/` paths. Every one of those plans imports `routes` (and, transitively via the shared layout, `Header`/`Footer`) from the old locations, and each plan's own build-verification step (`pnpm --filter web build`) compiles the whole app including the shared layout — so this move must land and build cleanly before any Wave 2 plan starts, or all three would build against a stale, soon-to-be-deleted path.
Output: `apps/web/shared/lib/routes.ts` and `apps/web/shared/components/{header,footer,logo,theme-toggle}.tsx` exist with identical exports/behavior to their Phase 1 originals; `apps/web/lib/` and `apps/web/components/` no longer exist; `apps/web/app/layout.tsx` and `apps/web/app/not-found.tsx` import from the new paths; `pnpm --filter web build` passes.
</objective>
