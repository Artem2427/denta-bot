## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| curl/browser client → `POST /auth/refresh` | Cookie-authenticated, high-value target — a leaked or replayed refresh token is the single highest-impact threat in this phase |
| curl/browser client → `POST /auth/logout` | Must only ever act on the caller's own session, never an arbitrary one |
| Any future controller → global `AccessTokenGuard` | Fail-closed default; the boundary a forgotten guard on a Phase 5 route would otherwise silently cross |

|-----------|----------|-----------|----------|-------------|------------------|
| T-04-02-01 | Spoofing | `POST /auth/refresh` — stolen/replayed refresh token | critical | mitigate | Rotation + reuse detection: any presentation of an already-consumed token revokes the whole `familyId`, killing even the legitimately-rotated newest token |
