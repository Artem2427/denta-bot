# Phase 06.2: Single-Page Landing Consolidation + i18n (apps/web) - Context

**Gathered:** 2026-08-19
**Status:** Ready for planning

<domain>
## Phase Boundary

Collapse `apps/web`'s Home, Prices, Contacts, and Demo pages into a single scrolling landing page at `/`, with section structure and sales copy sourced from the design export `DentaBot Landing.dc.html` (header, hero, problem/solution, how-it-works, admin-panel showcase, features, pricing, reviews, unified lead-capture, FAQ, footer — all as anchor sections). Add URL-based locale routing for uk (default)/ru/en covering the landing page and site chrome (Header/Footer/nav). `/prices`, `/demo`, `/contacts` are retired as destination routes — their content and working functionality (real pricing data, real lead-capture POST, the interactive bot/admin demo) get folded into landing-page sections, not deleted. `/blog` and `/blog/[slug]` remain the only other real routes, staying Ukrainian-only this phase (no locale variants for blog content).

This phase supersedes the previously in-progress quick task `260818-wjz` (per-button "Демо" link rewiring to the DemoCta modal) — dropped as moot; the new landing page's own lead-capture section replaces that pattern entirely. It also supersedes Phase 06.1's multi-page premium restyle for the pages being merged (06.1 already delivered the `dt-*` token system and shared primitives this phase reuses — no restyle work needed, just recomposition).

<decisions>
## Implementation Decisions

### Page/route consolidation
- **D-01:** Only `/` (single scrolling page) and `/blog`, `/blog/[slug]` remain as real destination routes. `/prices`, `/demo`, `/contacts` are retired as destinations — content folds into `/` as anchor sections (`#pricing`, `#lead`, demo/how-it-works section). — **Reversibility:** costly — undoing means re-splitting sections back into standalone routed pages and re-threading nav/links.
- **D-02:** The in-progress quick task `260818-wjz` (retire `/demo` as a destination, rewire "Демо" CTAs to open a lead modal) is dropped/superseded — its directory was already removed from `.planning/quick/`. Do not resume or reference it.
- **D-03 (Claude's discretion, noted not asked):** Whether `/prices`, `/demo`, `/contacts` should 301-redirect to `/#pricing` etc. or simply 404/be removed from the route tree is left to planning — site has no production traffic yet (still mock-data-era until Phase 6, which just shipped), so redirects are a nice-to-have, not a requirement.

### Pricing section data source
- **D-04:** The pricing section stays wired to the real `PricingPlan` API from Phase 6 (`GET /public/pricing-plans`) — no hardcoding, no reverting the CMS wiring. The DB's `PricingPlan` rows get **reseeded** with the design file's sales copy (Старт/Клініка/Мережа: names, `for` blurb, price, `items[]`, `tag`, `cta` label) so the live-fetched data matches the new design. — **Reversibility:** reversible — reseeding is a data change via existing `platform-admin` CRUD or a seed script, not a schema change.
- **D-05 (Claude's discretion):** Exact mechanism for reseeding (seed script vs manual `platform-admin` edits vs a one-off admin API call) left to planning.

### Lead capture form
- **D-06:** The single `#lead` section reuses the existing **Contacts form** (`apps/web/modules/contacts/contact-form.tsx`) fields and zod schema (name/clinic/contact/message), POSTing to the real `/leads` API with `source: contacts` — the existing `LeadSource` enum (`contacts | demo`) is NOT changed, no Prisma migration needed. — **Reversibility:** reversible — purely a component-reuse/placement decision, enum untouched.
- **D-07:** `demo-lead-form.tsx` (currently used by the Demo page's "Замовити демо" modal, tags `source: demo`) stays available for the demo/how-it-works section's own CTA if that section keeps its own modal trigger, OR the whole page funnels to the one `#lead` section instead — this composition detail is Claude's discretion at planning time, as long as `source: contacts` is what the primary `#lead` section sends per D-06.

### i18n scope & routing
- **D-08:** URL-based locale routing, uk as default/unprefixed (`/` = Ukrainian), `ru`/`en` prefixed (`/ru/...`, `/en/...`) — next-intl "as-needed" locale-prefix pattern (or equivalent). — **Reversibility:** costly — switching prefix strategy later touches every route/link/sitemap.
- **D-09:** i18n scope for this phase = the landing page (`/`) and site chrome (Header nav, Footer, any shared UI strings) only. Blog (`/blog`, `/blog/[slug]`) stays Ukrainian-only — `BlogPost` has no locale field/rows, and adding one is out of scope for this phase (explicitly deferred, not silently dropped). — **Reversibility:** reversible — blog i18n is additive later (new schema field/rows), doesn't conflict with this phase's routing setup.
- **D-10:** Claude translates/adapts the ru/en marketing copy from the design file's Ukrainian text (same persuasive intent, not a literal word-for-word translation) — user is not supplying separate ru/en copy.
- **D-11 (Claude's discretion):** Exact i18n library/mechanism (next-intl vs an alternative), message-file structure, and how `PricingPlan` API data (D-04, Ukrainian-only in the DB) is presented on `/ru` and `/en` pages (translate at render time, or show Ukrainian pricing content even on localized page shells) are left to research/planning — no explicit user preference beyond "URL-based routing for uk/ru/en."

### Claude's Discretion
- Demo/how-it-works section style: whether to keep the existing interactive Telegram-bot chat simulation + admin-panel tab-switcher (`demo-tabs.tsx`/`bot-tab.tsx`/`admin-tab.tsx`, currently at `/demo`) embedded as a landing-page section, or simplify to the raw design's static 3-step explainer + screenshot placeholder. Not discussed with user — deferred to planning/research to weigh effort vs "site should not be overloaded" instruction. Leaning toward keeping the interactive simulation since it's already built, on-brand, and more compelling than a static screenshot, but this is not locked.
- Exact section order and which existing Home modules (`hero.tsx`, `problem.tsx`, `solution.tsx`, `features.tsx`, `cta-banner.tsx`, `testimonials.tsx`, `unified-source.tsx`) map onto the design file's sections vs get folded/dropped/rewritten.
- Whether `/prices`, `/demo`, `/contacts` routes redirect (301) to landing anchors or are removed from the route tree (D-03).
- FAQ content/count, reviews content, feature-grid copy — adapt from the design file's Ukrainian copy, "rewritten to sell" per the client's original instruction; exact wording is Claude's discretion within that intent.

</decisions>
