## Phase Goal

**As a** site visitor, **I want to** see every page wrapped in a consistent, themeable header and footer with working navigation and a proper 404 for bad links, **so that** the site feels complete and on-brand from my very first visit.

This plan activates the vertical slice: it consumes Plan 01-01's re-themed tokens and wires the actual, user-visible shell (header, footer, theme toggle, logo, 404) into every route via the root layout — the point where a real visitor can, for the first time, load any URL and see the branded shell with a working theme toggle.

<objective>
Build the DentaBot logo, theme toggle, header, and footer components local to `apps/web`, add the Next.js root Not Found route, and wire all of it into `apps/web/app/layout.tsx` alongside `next-themes`' `ThemeProvider` and `@repo/ui`'s `Toaster`.

Purpose: this is the shared shell every future page (Phase 2/3) renders inside — get the Client/Server boundary, active-link semantics, and token usage right once, here, so it never needs revisiting.
Output: a working `pnpm dev:web` session where every route (including unmatched ones) renders inside the branded, theme-toggleable header/footer shell.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → external anchor targets (Telegram/Instagram, footer) | User-initiated navigation to a third-party origin via `target="_blank"` |
| Browser `localStorage` (next-themes) → `<html>` class attribute | Client-only state, no server round-trip, no user-supplied free text |
| Any URL → `app/not-found.tsx` | Unauthenticated, unvalidated path input reaching the Next.js router (framework-level, not custom code) |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-03 | Tampering / Spoofing (reverse tabnabbing) | `apps/web/app/_components/footer.tsx` (Telegram/Instagram anchors) | medium | mitigate | `rel="noopener noreferrer"` required on both external anchors (Task 2 acceptance criteria greps for exactly 2) — prevents the opened tab from gaining `window.opener` access back to this site |
| T-01-04 | Tampering (theme value) | `next-themes` `localStorage` `'theme'` key | low | accept | `next-themes` only ever reads/writes its own constrained enum (`'light'`/`'dark'`/`'system'`), never renders the stored value as HTML — no injection surface (01-RESEARCH.md Known Threat Patterns) |
| T-01-05 | Spoofing (silent redirect masking a bad URL) | `apps/web/app/not-found.tsx` | low | mitigate | No client-side redirect/`useRouter().push` in a `useEffect` — user always sees the 404 content and navigates home via an explicit button click (Task 2 prohibition, acceptance criteria greps for absence) |
| T-01-SC | Tampering (supply chain) | npm/pip/cargo installs | high | accept | No new package installs occur in this plan — every import (`next-themes`, `lucide-react`, `next/link`, `next/navigation`, `@repo/ui`) is a pre-existing dependency confirmed in 01-RESEARCH.md's Package Legitimacy Audit |
