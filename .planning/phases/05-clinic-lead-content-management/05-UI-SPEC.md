# Phase 5 — UI Design Contract

> Visual and interaction contract for `apps/platform-admin`'s Clinic/Lead/Content Management screens.
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Locked directive (user, non-negotiable):** "используем все компоненты и tailwind c папки packages/ui" — this phase's entire UI is built on `@repo/ui` (`packages/ui`) — its existing shadcn/Radix component set, CVA variants, and `packages/ui/styles/theme.css` Tailwind v4 token system. `apps/platform-admin` does **not** get its own `components.json`, its own token file, or the `apps/web` premium `dt-*` design system. This matches CLAUDE.md's existing constraint that `packages/ui`/`theme.css` stays authoritative for `apps/admin-panel`-lineage apps (which `apps/platform-admin` is).

### Gap 1 — `Form` (react-hook-form binding primitive): MISSING, scope into `@repo/ui` this phase

**Decision:** Add `packages/ui/src/components/shadcn-ui/form.tsx` (shadcn's standard `Form`/`FormField`/`FormItem`/`FormLabel`/`FormControl`/`FormDescription`/`FormMessage` set, built on `react-hook-form`'s `Controller`/`FormProvider` + Radix `Label`/`Slot`, both already `packages/ui` dependencies). This is **not** a plan-time/app-level decision — it goes into `packages/ui` because:
- CLAUDE.md requires all `platform-admin` UI go through `@repo/ui`; a form primitive used by 4 separate create/edit flows (Clinic, Lead status, Blog Post, Pricing Plan) is exactly the kind of primitive the constraint is protecting against being duplicated 4x.
- The user's own memory note explicitly permits extending `@repo/ui` with new variants/primitives, provided palette consistency is kept (no new colors are needed for `Form` — it inherits `Input`/`Label`/`destructive` tokens already in `theme.css`).
- `react-hook-form` needs to be added as a `packages/ui` dependency (version `^7`, matching `apps/web`'s existing pin per CLAUDE.md's forms constraint) — it is currently only a dependency of `apps/web`, not `packages/ui`.

**Planner action item:** add a Wave-0 task: `pnpm --filter @repo/ui add react-hook-form` + create `form.tsx` (hand-port shadcn's public `form.tsx` source, since it is a standard, unmodified shadcn official-registry primitive — no third-party registry involved, no vetting gate required) + add the `./src/components/shadcn-ui/form` export line to `packages/ui/index.tsx`.

### Gap 2 — `DataTable` (TanStack Table wrapper): MISSING, scope into `@repo/ui` this phase

**Decision:** Add a new `DataTable` composition to `packages/ui/src/components/shadcn-ui/data-table.tsx` (or `packages/ui/src/components/data-table/` if split into sub-files), built on `@tanstack/react-table`'s `useReactTable`/`getCoreRowModel`/`getSortedRowModel`/`flexRender`, composing the **existing** `Table`/`TableHeader`/`TableRow`/`TableHead`/`TableBody`/`TableCell` primitives plus the **existing** `Pagination` primitive for its footer. There is no single-command shadcn registry install for this (`data-table` is a documented shadcn *pattern*, not an installable `npx shadcn add data-table` block) — it must be hand-composed, but from primitives already fully present and audited in `packages/ui`.

**Scope for this phase (keep minimal — do not over-build):**
- `DataTable<TData>` — core table render (columns + data → rendered `Table`)
- `DataTableColumnHeader` — sortable column header button (chevron icon from `lucide-react`, already available)
- `DataTablePagination` — page-size/page-index footer, wraps the existing `Pagination` primitive
- No column-visibility toggle, no row-selection, no drag-reorder — none of CLINIC-01/CLINIC-05/LEAD-03/LEAD-06/CMS-01/CMS-03 require them; adding them now would be scope creep beyond this phase's requirements.

**Planner action item:** add a Wave-0 task alongside Gap 1, since both are foundational primitives every list screen (Clinics, Leads, Blog Posts, Pricing Plans) depends on — build these **before** any CRUD screen task, not inline with the first screen that happens to need one.

## Spacing Scale

Declared values (must be multiples of 4) — inherited as-is from Tailwind v4's default spacing scale already in effect via `theme.css`; no phase-specific override:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps (nav items, badge icons) |
| sm | 8px | Compact element spacing (form field label-to-input gap, badge padding) |
| md | 16px | Default element spacing (card padding, form field vertical gap, table cell horizontal padding beyond the `@repo/ui` `TableCell` default) |
| lg | 24px | Section padding (page header to content, `CardHeader`/`CardContent` block separation) |
| xl | 32px | Layout gaps (sidebar-to-content gutter, page-level top margin) |
| 2xl | 48px | Major section breaks (Content tab body top margin) |
| 3xl | 64px | Not used this phase — no marketing-style hero/section spacing needed in an internal dashboard |

Exceptions: `@repo/ui` component-internal spacing (e.g. `Table`'s `TableHead`/`TableCell` use `h-10`/`p-2` = 40px row height / 8px cell padding; `Button` default height is `h-9` = 36px) is inherited from the component and must **not** be overridden per-screen — consistency across Clinics/Leads/Content lists depends on every `DataTable` using identical row/cell dimensions.

**Dimension 2 recommendation, addressed:**
- **Focal point per screen type:** List screens (Clinics, Leads, Blog Posts, Pricing Plans) — the `DataTable` is the primary focal point, positioned directly below the page title (`Display`, 24px) + primary CTA row. Detail screens (Clinic/Lead/Post/Plan) — the record's `Card` is the focal point, with the trace-field line (`INFRA-05`) as a secondary, visually de-emphasized element beneath it (see Copywriting Contract's "Trace field display" row).
- **Icon-only row actions:** Every icon-only `DataTable` row action (e.g. the Delete icon button on Blog Posts/Pricing Plans rows) MUST carry an `aria-label` (e.g. `aria-label="Delete post"`) — icons alone are never a sufficient accessible name. Planner/executor treat this as a hard requirement for every icon-only `Button`, not just Delete.
